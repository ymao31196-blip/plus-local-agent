# QMD工作区索引试验 — 2026-10-28

## 目标与边界
探索直接复用开源QMD（`@tobilu/qmd@2.8.3`，MIT）来满足PLA“一个工作区一份索引”的需求，先用隔离测试目录验证Windows、中文检索、增量刷新和MCP集成；不修改正式科研资料。

## 实际操作
1. 确认本机有`D:\\nodejs\\node.exe`（Node 24.19），PLA Desktop自带`D:\\PLA Desktop\\resources\\node.exe`（具体规范化路径`\\\\?\\D:\\PLA Desktop\\resources\\node.exe`）。
2. 使用`runtime.provider_import`导入`qmd-pilot`，`autostart=false`，`executable_stdio`，入口为`node_modules/@tobilu/qmd/dist/cli/qmd.js mcp`，allowlist仅包含`status`、`metadata`、`query`、`get`、`multi_get`；不激活。
3. 使用`runtime.desktop_package_preview` / `desktop_package_commit`固定npm包版本，使用`runtime.desktop_install_preview` / `provider_setup`按SHA审核后启动私有安装，安装位置在`%LOCALAPPDATA%\\io.pla.desktop\\components\\.provider_envs\\qmd-pilot`，非全局npm。
4. 在`C:\\Users\\26286\\Desktop\\PLA-QMD-pilot-20261028`写入3份原创测试Markdown、项目本地`.qmd/index.yml`以及仅用于隔离测试的`verify-qmd.ps1`（不自动执行）。配置中无`update:`脚本、外部collection路径或自定义模型URI。
5. 运行状态需以`runtime.desktop_install_status`的最新结果为准；**没有最终成功回执时不能认定已安装完成**。

## 架构结论
原生QMD MCP暴露查询、读取和状态接口，`qmd init`/`qmd update`仍为CLI操作；当前`qmd-pilot`MCP进程的工作目录固定在组件隔离环境，不能自动使用用户每次选择的另一个工作区的`.qmd/index.yml`。因此原生MCP可以作为可选查询组件验证，最终PLA产品功能仍需要小型受控适配层：仅对已授权root设置项目索引路径、执行初始化/刷新/检索、限定结果路径并遵循QMD信任策略。不要将普通Node.js或任意shell添加为全局高权限执行入口。

## 2026-10-29 真实PLA_TEST继续验收

- 上次npm安装任务已不在运行，`runtime.desktop_install_status`显示idle且未记录`qmd-pilot`安装回执；不能倒推安装器成功结束。然而QMD CLI已经实际运行，能生成项目本地SQLite索引、执行检索，因此**功能性可用已证明，安装流程的完成回执仍需单独复核**。
- `qmd-pilot`原生MCP由PLA热重载进入ready。原清单要求的`metadata`未被实际MCP发现（官方近期文档列有该能力）；将试验Allowlist收缩到`status/query/get/multi_get`后，4项成功发现，`qmd-pilot.status`返回组件自身默认索引0 documents。原生MCP的固定cwd与用户工作区不一致，不能直接满足工作区索引。
- 在`scripts/qmd_pilot_control.mjs`新增**仅试验用途的固定目录MCP桥接**，以PLA自定义组件`qmd-pilot-control`导入，热重载后成功发现`pilot_run`。该桥接仅接受`update/status/search`固定操作和最长120字符的查询，使用无shell子进程调用已安装QMD CLI；工作区路径固定为Desktop的`PLA-QMD-pilot-20261028`；启动前验证目录真实路径和批准的配置SHA-256；剔除通用环境凭据和`QMD_TRUST_LOCAL_CONFIG`等信任绕过变量，70秒超时，结果限24KB。不为PLA全局执行器添加Node.js或npm执行权限。
- 首次`update`生成`.qmd/index.sqlite`，报告3 new。QMD首次刷新将其内置模型默认值写入`index.yml`，经检查无更新Hook或外部索引路径后将新配置SHA加入试验白名单；没有调用`embed`，未下载模型。后续`status`报告3 indexed、0 vector、数据库约120KB。
- 检索`WRF`命中`notes/wrf-notes.md`与`figures/workflow.md`；`复杂地形`和`尾流效应`命中`notes/cfd-notes.md`；文件名、标题、上下文、行号及片段均能返回。短词`风`命中多个文件但评分均为0，中文短词排序质量需专项评估。
- 第二次`update`报告3 unchanged；改动一份Markdown后报告1 updated、2 unchanged，检索能找到新增`尾流效应`；改扩展名后报告1 removed，搜索结果清空；恢复文件扩展名后报告1 new，文件与索引恢复。故意添加配置注释即触发桥接的SHA拒绝，随后原样恢复配置SHA校验通过。测试中所有修改只发生在独立试验目录；没有接触`硕士课题`。
- 桥接的`autostart=false`，需要PLA手动热启，适合工程可行性验证；**不是可泛化发布的工作区索引组件**。正式版需要以PLA授权Root注册表为权威，动态选项目、限定实际路径、更新/搜索结果再次核对路径归属、按最小权限设计读写操作和索引状态，避免把固定硬编码路径带入发布版本。
