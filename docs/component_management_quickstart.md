# 组件与 MCP 插件使用指南

本次更新为 PLA Desktop 1.0.0-rc.10 测试发行候选。当前构建和安装验收进度见 [修复记录](component_management_repair_status.md)。修改源码不会自动更新正在运行的安装版。

## 添加和安装

1. 打开「组件与 MCP 插件 → 仓库管理」，添加本地 file:/// 或 HTTPS 仓库 URL。
2. 点击仓库的 Browse，或打开「浏览组件」并刷新，查看组件详情、版本、来源和许可证。
3. 点击安装，审核完整依赖、清单、文件校验值和目标目录。确认后显示后台任务进度；等待完成再操作。
4. 到「本机组件」刷新目录，启动 Runtime，再启用对应插件。检查实际连接状态，通过「工具与参数」查看完整 Schema。
5. 在 ChatGPT 中调用插件工具，并单独记录端到端验证。本地安装成功不等于 Tunnel 或 ChatGPT 已通过。

安装包自带 Node，Python 组件按需下载校验过的安装工具与私有 Python。普通用户无需安装 Rust、Node 或 Python，也无需运行开发脚本。组件安装需要联网。

## 升级、健康检查和卸载

升级前先在本机组件停用插件。审核新版本计划，等待升级任务完成，再启用并验证工具调用。升级后的旧版本有明确所有权记录，卸载会处理全部已登记版本。

「本机组件」同时提供仓库安装版本、安装完整性检查及卸载。它不会把文件存在当成 MCP 连接成功；连接状态以本机组件的真实 Runtime 观察为准。

卸载前必须先停用。审核已登记的安装信息，等待后台任务完成。修改过的清单或资产会阻止卸载，未知文件保留。移除仓库只移除来源登记，不卸载组件。

## 开发者测试仓库

本项目已有测试仓库，可在开发机器添加：

`file:///D:/AI_Tools/plus-local-agent/test-provider-repository`

其中 test-echo-provider 使用固定的 mcp==2.2.0 和 MCPServer 接口。安装并启用后，可调用 echo_message 和 echo_structured。该仓库仅用于开发验收，不随发行包自动添加。

发布者可使用 scripts/create_test_repository.py 创建示例，再按照 [仓库协议](provider_repository_protocol.md) 编写自己的仓库。Git 仓库、索引签名和任意安装钩子尚不支持。

## 来源和权限

文件 SHA-256 校验确认实际安装的是已审阅内容，不证明仓库发布者可信。依赖隔离不是操作系统沙箱。启用 Provider 后，其代码以当前用户身份运行；应审核源代码和工具白名单。PLA 的工具路由、工作区权限和确认规则保持原有边界。

遇到失败时查看任务日志与「日志与诊断」。字符串 RPC 错误会显示具体原因；不要因为界面显示任务已开始就认定成功。
